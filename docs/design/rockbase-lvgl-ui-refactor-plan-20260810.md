# Rockbase LVGL LCD UI 架构记录

## 文档目的

本文档记录 2026-08-10 这轮 LCD UI 滑动抖动改造的结论、当前架构和后续维护规则。

它不是临时流水日志。后续继续改 LVGL 页面时，应先读本文档。

## 原始问题

接入真实监控数据后，LCD 页面左右滑动时出现页面内对象抖动。问题不是页面整体跳动，而是卡片、文字等对象在滑动过程中有轻微抖动，视觉上容易发晕。

早期两个小修补没有根治：

- 跳过未变化 label 更新。
- 触摸期间延后部分状态刷新。

最终判断：问题是架构级的。旧实现把 LVGL `tileview` 移动、页面对象实时刷新、页面截图缓存、软件旋转、DRM present、触摸处理混在一个主循环里。滑动过程中可能同时发生页面移动和对象刷新，因此会产生视觉不稳定。

## 产品需求

- 四个横向页面。
- 每页有全屏底图。
- 底图上叠加少量监控值。
- 时间类信息可 1 秒刷新。
- Bitcoin、System、Network 等状态默认 2 到 5 秒刷新。
- 高频字段必须按需启用，不应影响滑动。
- 左右滑动必须顺滑。
- 滑动过程中页面内容不应重排、闪烁或更新。

## 当前架构

当前改造方向是把“数据刷新”和“滑动合成”分离。

### UiModel

`UiModel` 是从 `/tmp/status-api.json` 和本地时间生成的数据快照。

数据路径负责：

- 文件 IO。
- JSON 解析。
- 字段格式化。
- 按页面判断 dirty。

显示路径只消费已经解析好的模型，不在关键显示路径里做文件 IO 或 JSON 解析。

### 页面渲染

每个页面都应被视为独立 renderer：

- Bitcoin 页面。
- Stratum 页面。
- System 页面。
- Network 页面。

页面 renderer 负责：

- 创建该页面的 LVGL 对象。
- 只在值变化时更新 label。
- 只在页面 dirty 且 pager 空闲时重建页面缓存。

### Pager Compositor

当前不再依赖 LVGL `tileview` 做实时滑动合成。

滑动路径应遵守：

- 触摸时只更新 `visual_scroll_x`。
- 滑动期间只从已缓存页面 buffer 拷贝/合成到 DRM buffer。
- 滑动期间不允许 LVGL 对象刷新直接参与 present。
- 松手后执行确定性的吸附动画。
- 当前吸附动画时间为 `300ms`。
- 吸附结束后再同步隐藏的 LVGL 页面状态。

## 已验证结果

在 `192.168.124.28` 1G 真板热部署验证后，用户确认：

- 页面滑动明显更顺滑。
- 300ms 吸附动画效果符合预期。
- 后续修复过 `Block time` 行内布局、日期/时间宽度和颜色细节。

## 后续维护规则

继续改 LCD UI 时遵守：

- 不要回到“滑动时实时刷新 LVGL 对象”的路径。
- 数据刷新可以延后，但滑动合成必须稳定。
- 页面内容更新应尽量只发生在 pager idle 时。
- 页面布局小改必须先热部署到 `124.28` 验证。
- 验证通过后再固化到 rootfs overlay。
- 如果新增图表或动态效果，优先让它只在当前页 idle 时刷新。

## 后续可优化项

- 继续拆分页面 renderer，降低 `main.cpp` 单文件复杂度。
- 尽量让页面缓存使用物理显示方向，减少每帧旋转成本。
- 保留低频性能日志，例如 model refresh 耗时、cache rebuild 耗时、present 间隔。
- 不要恢复高频 UI 调试日志。
